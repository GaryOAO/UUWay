# UU Remote 4.42.0.2770 review for the native Wayland bridge

This records the 2026-09-25 upgrade of the native (non-RDP) installation from
`4.39.2.1561`. It applies to the native service only: the legacy relay still
needs a reviewed server patch manifest, and none exists for this release.

## Exact release identity

- Official installer SHA-256:
  `d3a7776f6fb00b196e2fcbf8acba06fd52b19437b0da80fec0ae838ee362f06f`
- `GameViewerServer.exe` SHA-256 (unpatched):
  `0ee0a46aa715a48c7f47c3dbfd9477bf31295bc17ce0caa1401d3de0120bf6fd`
- `GameViewerHealthd.exe` SHA-256:
  `872491f2e3e17a91a2f75bfe42d484892d0da7bd535113833df0706ac0bad015`

The installer was first run only inside the networkless Bubblewrap staging
sandbox (`scripts/stage-uu-release.sh --sandbox-install`).

## Input: no server patch

The `gvinput` kernel-driver path, which the 4.33–4.39 patches disabled, is gone.
A new `SwitchingInputInjector` starts on `send_input`
(`input_backend_initialized backend=send_input`) and moves to its virtual HID
backend only after a successful probe, staying on `send_input` when it cannot
open it (`vhid_open_failed`). `audit-gameviewer.py` finds no site for the
constructor patch, and the two remaining byte matches only store the virtual
mouse setting. The server therefore runs unpatched; the native input hook
attached to it at startup (`native_input_hook_ready`).

## Capture, encoding, cursor and display: unchanged boundaries

`streamer.dll` changed, but its relevant imports are identical to 4.39.2:
`dxgi!CreateDXGIFactory1`, `d3d11!D3D11CreateDevice`, `USER32!SendInput`,
`GetCursorInfo`, `EnumDisplaySettings(Ex)W`, `QueryDisplayConfig`,
`GetDisplayConfigBufferSizes` and `DisplayConfigGetDeviceInfo`. NVENC is still
loaded dynamically through `NvEncodeAPICreateInstance`. The server lost only
two `SetupDi` imports that belonged to the removed driver. The version-pinned
contract audits (`audit-uu-*-contract.py`) intentionally reject this build;
the native runtime depends on the public interfaces above, not their offsets.

## Terminal

`conpty_bridge.exe` changed but keeps the same switches and psmux script
steps, and the bundled Microsoft `conpty.dll` is byte-identical, so the shim
still replaces it. The launch script now runs chcp by path
(`& '...\chcp.com' 65001 | Out-Null`), which the PowerShell proxy accepts.
The pane command names the system PowerShell path, where the proxy already
lives. See [the design notes](../design.md#terminal).

## Upgrade procedure used

1. Stop `uu-native-bridge.service` and wait for `wineserver -w`.
2. Copy the whole prefix aside (about 4 GB).
3. Run the official installer with `/S` in the prefix; reinstall
   `bin/powershell.exe` from `compat/uu-terminal-proxy.exe`, since 4.42 ships
   none.
4. Start the service and roll back to the copy if it is not active, restarts,
   or loses `GameViewerServer.exe` within five minutes.

Controller acceptance (display, input, IME, resolution changes, terminal) is
recorded separately after a real session.
